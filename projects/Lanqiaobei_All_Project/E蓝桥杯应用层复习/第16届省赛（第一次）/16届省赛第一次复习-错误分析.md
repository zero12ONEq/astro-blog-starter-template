## P0 致命问题

### 1. `relay_old` 声明为局部变量 —— 继电器计数全面失准

**位置：** `main.c` 第166行，`led_proc()` 函数内部

**你的代码：**
```c
void led_proc()
{
    bit relay_old;  // ← 局部bit变量！
    if(!led_relay_lock)
    {
        ...
        if(hot_flag==1&&close_flag==1)
        {
            Relay(1);           // ← Relay(bit enable) 的 enable 参数也是 bit
            if(relay_old==0)    // ← 此时 relay_old 可能已被 Relay() 的参数覆盖
            {
                relay_count++;
            }
            relay_old=1;
        }
        else
        {
            Relay(0);
            relay_old=0;
        }
    }
    ...
}
```

**满分代码：**
```c
idata bit Relay_Old;  // ← 全局变量，第24行

void Led_Proc()
{
    if(!Relay_Led_Lock)
    {
        ...
        if(Distance_Flag==1&&Htemperature_Flag==1)
        {
            Relay(1);
            if(Relay_Old==0)
            {
                Relay_Count++;
            }
            Relay_Old=1;
        }
        ...
    }
}
```

**根因分析：**

在C51编译器中，`bit` 类型变量**不在栈上分配**，而是统一存放在**位寻址区**（内部RAM 20H-2FH，共128个位）。编译器对局部 `bit` 变量做 **overlay 优化**——不同函数的局部 `bit` 变量和 `bit` 参数会**复用同一个位地址**。

具体来说：
1. `led_proc()` 内的局部 `bit relay_old` 被分配到某个位地址（如 00H.0）
2. `Relay(bit enable)` 的参数 `enable` 也是 `bit` 类型，编译器可能将其分配到**同一个位地址**
3. 调用 `Relay(1)` 时，`enable=1` 写入该位地址 → `relay_old` 被覆盖为 1
4. 紧接着检查 `if(relay_old==0)` → **条件为假**，`relay_count++` 不执行

**影响范围：** 直接导致测试点 38、41、54、57、66 全部失败（NC计数偏低）。

**解决方案：** 将 `relay_old` 移到全局声明区：
```c
// 在全局变量声明区添加
idata bit relay_old;

// led_proc() 内删除 bit relay_old; 这一行
```

### 2. `distance_sub` 未初始化 —— 首次运动状态判断使用垃圾值

**位置：** `main.c` 第255-296行，`distance_proc()` 函数

**你的代码：**
```c
void distance_proc()
{
    unsigned char distance_sub;      // ← 局部变量，未初始化（随机垃圾值）
    unsigned char temp_motion_state;
    if(distance_slow_down<999) return;
    distance_slow_down=0;

    distance_val=Ut_Wave_Data();
    if(distance_val<distance_para)   // ← 首次就判断接近
        close_flag=1;
    else
        close_flag=0;

    if(got_dis_flag)                 // ← 首次调用时 got_dis_flag=0，走else
    {
        distance_sub=abs(distance_val-distance_old);  // 仅此分支赋值
        distance_old=distance_val;
    }
    else
    {
        distance_old=distance_val;
        got_dis_flag=1;
        // ← distance_sub 仍然是垃圾值！没有赋值！
    }

    if(!suoding_flag)                // ← 首次调用时 suoding_flag=0，进入
    {
        if(distance_sub<5)           // ← 使用垃圾值判断！
            temp_motion_state=0;
        else if(distance_sub<10)
            temp_motion_state=1;
        else
            temp_motion_state=2;     // ← 垃圾值大概率≥10，错误判为"跑动"

        if(temp_motion_state!=motion_state)  // 0→2，状态变化
        {
            motion_state=temp_motion_state;  // ← 错误地设为"跑动"
            suoding_flag=1;                  // ← 锁定3秒
            suoding_tick=0;
        }
    }
    ...
}
```

**满分代码的正确处理：**
```c
void Get_Distance()
{
    ...
    if(First_Get_Distance==1)        // ← 只有非首次才进入完整判断
    {
        Distance_Val=Ut_Wave_Data();
        Distance_Sub=abs(Distance_Val-Distance_Old);
        Distance_Old=Distance_Val;
        Distance_Flag=(Distance_Val<Distance_Para);  // ← 接近判断也在内部

        if(!State_Change_Flag)
        {
            // 运动状态判断...
        }
        // stay/paihuai/run 标志更新...
    }
    else                             // ← 首次只记录距离，不做任何判断
    {
        First_Get_Distance=1;
        Distance_Val=Ut_Wave_Data();
        Distance_Old=Distance_Val;
        // 直接结束，不判断运动状态
    }
}
```

**后果链：**
1. 上电约1秒后首次采集距离
2. `distance_sub` 为垃圾值（大概率≥10）
3. `motion_state` 被错误设为2（跑动），`suoding_flag` 锁定3秒
4. `run_flag` 被设为1 → L8 立即开始闪烁（应该是熄灭的）
5. → **测试点2**：徘徊状态时"存在错误状态指示灯"（因为初始错误状态影响后续判断时序）
6. → **测试点4**：L8闪烁间隔error（从错误时间点开始闪烁，相位/时序与预期不符）

**解决方案：** 重构 `distance_proc()`，将所有判断逻辑移入 `got_dis_flag==1` 的分支：
```c
void distance_proc()
{
    unsigned char distance_sub;
    unsigned char temp_motion_state;
    if(distance_slow_down<999) return;
    distance_slow_down=0;

    if(got_dis_flag)
    {
        distance_val=Ut_Wave_Data();
        distance_sub=abs(distance_val-distance_old);
        distance_old=distance_val;

        if(distance_val<distance_para)
            close_flag=1;
        else
            close_flag=0;

        if(!suoding_flag)
        {
            if(distance_sub<5)
                temp_motion_state=0;
            else if(distance_sub<10)
                temp_motion_state=1;
            else
                temp_motion_state=2;
            if(temp_motion_state!=motion_state)
            {
                motion_state=temp_motion_state;
                suoding_flag=1;
                suoding_tick=0;
            }
        }
        if(!led_relay_lock)
        {
            stay_flag=(motion_state==0);
            paihuai_flag=(motion_state==1);
            run_flag=(motion_state==2);
        }
    }
    else
    {
        distance_val=Ut_Wave_Data();
        distance_old=distance_val;
        got_dis_flag=1;
    }
}
```

## 经验教训

1. **`bit` 类型变量绝对不要声明为局部变量** —— C51的bit变量在位寻址区分配，编译器会做overlay优化。局部bit变量与其他函数的bit参数可能共享同一位地址，导致值被意外覆盖。所有bit变量必须声明为全局的 `idata bit`。
2. **首次采集必须特殊处理** —— 涉及"前后两次数据对比"的逻辑（如运动状态检测的ΔL），首次采集时只记录数据，不做判断。所有判断逻辑应放在"已有历史数据"的分支内。
3. **局部变量必须初始化** —— 尤其是用于条件判断的变量，如果存在不被赋值就使用的执行路径，必须给默认值。
4. **上轮修复引入新问题** —— `relay_old` 从"未声明"改为"局部声明"，看似修复了编译错误，实际引入了更隐蔽的overlay覆盖问题。修复bug时要理解满分代码**为什么**这样写，而不仅仅是"让它能编译通过"。
